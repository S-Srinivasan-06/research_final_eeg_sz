# Evidence figures: rules and measured numbers

Generated by `python -m szfusion.viz.evidence` (src/szfusion/viz/evidence.py) from the s1_gate 1 s fusion outputs on TUSZ v2.0.6 eval. No recording or patient ID is shown; the rules below select the same cases again from the same outputs.

## Panel rules (path.md section 5)

- 240 s window centred on the selected event and shifted to lie inside the recording. 19 referential electrodes (REF or LE reference as recorded), resampled to 256 Hz, 0.5-35 Hz display filter (Butterworth order 4, zero phase). Rows top to bottom: left temporal chain, left parasagittal chain, midline, right parasagittal chain, right temporal chain.
- Per-channel scaling: each trace is divided by its robust SD (1.4826 x median absolute deviation over the window); one row = 8 robust SD; values beyond +-0.9 row are clipped. Amplitudes are therefore comparable within a trace, not across traces.
- Dotted vertical lines: every 1 s (the scoring unit).
- Event band: blue = annotated seizure second (.csv_bi); green = second of a predicted event that overlaps an annotated second; teal = both; red = second of a false-alarm event (a predicted event overlapping no annotated second); hatched = not scored (recording tail without CatBoost cover). Predicted events = event point 1 of the fusion, frozen on dev: centred moving average over k = 61 s, threshold 0.1802, gaps <= 60 s merged, events shorter than 10 s dropped. The strip above shows that smoothed probability and the threshold (dashed); the black bracket marks the selected event (other events in the window are drawn by the same rules).
- Electrode cells: blue = a TCP bipolar channel touching the electrode carries a per-channel (.csv) seizure label in that second (OR over the channels). FZ and PZ lie on no TCP channel, so they can never be blue. Green = a detected second (green or teal in the band) in which the electrode's LinOSS occlusion importance is >= 0.5 x the window maximum; teal = blue and green; red = the same importance rule inside a false-alarm second.
- Occlusion importance: each of the 5 LinOSS seeds is run on the window (tokens of the window, padded to 240 s with mask 0) intact and with one electrode's 100 tokens set to 0 (the z-scored global mean) in every second; importance = intact logit - occluded logit, averaged over the 5 seeds; window maximum = over all 19 electrodes and all seconds of the window. It explains the LinOSS branch only; the CatBoost branch has no per-electrode attribution here.

Focal-type = all overlapping .csv labels in {fnsz, cpsz, spsz}; generalized-type = all in {gnsz, absz, tcsz, tnsz, mysz}. Latency = start of the first overlapping predicted event minus the annotated onset (negative = before onset; the centred smoothing looks ahead). 'Median' = the candidate closest to the median of the candidates (ties: smaller value, then store order).
